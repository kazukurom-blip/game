# デバッグ / テスト ガイド（v2）

## デバッグパネル（`src/debug/debug.js`）

プレイ中に **F2** または **`**（バッククォート）でトグル。画面右側に表示されます（画面内に収まることを smoke で確認）。

表示内容: FPS と **1フレームの処理時間（update+draw の ms, `game.perf`）**、経過時間、エンティティ数、現在マップ（n/34）、プレイヤー座標・速度・状態、Lv・HP・MP・所持金・手配度・heat、服破れ度、インベントリ使用数、**町/フィールド・地域・時刻・装備中の PET**、`game.lastError`（ない時は緑で「なし」）、直近4件の操作ログ。

ボタンはマウスでクリックできます。パネル表示中だけ、以下のホットキーも使えます。

| キー | 操作 | 内容 |
|---|---|---|
| F3 | 当たり判定 | 足場・地面・壁・ロープ・ポータル判定・出現エリア・各エンティティの判定。**夜の色調オーバーレイの上に描く**（暗くならない） |
| F4 | 無敵 | `debug.god = true` |
| F5 | Lv+1 | `gainExp` で次のレベルまで（演出・SP/AP あり） |
| F6 | HP-10% | 服破れの閾値を跨いだら `tear` エフェクト |
| F7 | 敵スポーン | **そのマップで実際に出る敵**を順番に前方 260px に出す（`game.spawner` の解決済み出現表 → 無ければ `ENEMIES[].habitats`。町では市民） |
| F8 | 全敵撃破 | 全敵に `damageEnemy`（経験値・ドロップ・図鑑・手配度も通常どおり） |
| F9 | マップワープ | `MAP_ORDER` 順（34マップ）に次へ。ボタンに `ワープ n/34` |
| F10 | ミッション即完了 | 進行中の目的を満たして `turnIn`（無ければ受注可能な最初のもの） |
| Shift+F3 | 全アイテム付与 | 48 枠を超える分はスキップ |
| Shift+F4 | お金+10000 | |
| Shift+F5 / F6 | 手配度 ±1 | フィールドで上げると「（フィールドでは警察は出ない。町で確認）」と表示。**警察が来るのは町だけ** |
| Shift+F7 | HP/MP 全快 | |
| Shift+F8 | インベントリ整理 | 赤/青ポーション以外を削除 |
| Shift+F9 | PET付与 | PET 10種を順番に付与して装備（押すたびに次の PET） |
| Shift+F10 | 全マップ訪問済み | `state.visited` に34マップすべて（ワールドマップ・タクシー確認用） |
| （ボタンのみ） | 時刻: 朝7時 / 昼12時 / 夕18時 / 夜22時 | `state.clock` を設定（背景の昼夜・夜の経験値+10% の確認用） |

コンソール / テストからは `game.debug.run('<id>')` で同じ操作を呼べます。
id: `hitbox, god, level, hpDown, spawn, killAll, warp, mission, items, money, wantedUp, wantedDown, hpFull, clearInv, pet, visitAll, clock_morning, clock_noon, clock_evening, clock_night`。
引数付き: `game.debug.spawnEnemy('boss_don')`、`game.debug.warp('casino')`、`game.debug.setLevel(40)`、`game.debug.setClock(22)`、`game.debug.givePet()`。

性能調査用: `game.debug.skip = {bg:1, tiles:1, ents:1, night:1, hud:1}` で描画レイヤーを個別に止められます。`game.debug.profile = true` で HUD の部位別描画時間が `game.debug.hudProf` に入ります。
`window` の `error` / `unhandledrejection` も拾って `game.lastError` に入れます。

## テスト

```bash
npm run test:unit    # node tests/unit.mjs              （約3秒）
node tests/unit.mjs --repeat=40                          # 乱数に依存するテストを40回繰り返す（フレーク検出）
```

## 残課題・気づいた点（提案）

- **夕方・夜の描画負荷（GPU 側）**: JS の処理は 3ms 程度まで下がりましたが、headless（ソフトウェア描画）では夕方・夜に 30〜40fps 程度です。原因は全画面の合成（背景の色調 `source-atop`、光バッファの加算、夜の暗がり `multiply`、夕方は暖色 `multiply` がもう1枚、空の `destination-over`）。通常の GPU 付きブラウザなら問題ない見込みですが、さらに軽くするなら「時刻を 15 分刻みにして色調済みのレイヤーをキャッシュ」「夕方の2枚の multiply を1枚にまとめる」が効きます（アート担当の範囲）。
- **町で車を運転すると市民をはねて手配度が上がりやすい**: テストでビーチを約1秒走っただけで★3 になりました。GTA 風としては仕様どおりですが、町で走る「ドライブ」系ミッション（m07: 300m、d04: 500m、s07: 800m）が警察に追われながらになります。市民が車を避ける、または車での市民ヒットの手配度を下げる案があります。
- **第13話の手間**: ★4 で警察を呼んで SWAT 隊員を10人倒す必要があります。修正後は★4 の出現が刑事と SWAT 隊員だけになりましたが、手配度は警官を倒すと上がり続けるため★5（重装SWAT混在）に上がりやすいです。目標の数を減らすか、★4〜5 の両方で数えると遊びやすくなります。
- **背景の看板の重なり**: decor（ゲーム側の小物）は直しましたが、背景シーン（`bgScenes.js`）に描かれている看板同士の重なり（夜景ブールバードの「LUCKY 7」など）は少し残っています（背景なので遊びには影響なし）。
- **町の看板の文字**: 宇宙港の町に「LIQUOR」のネオンなど、地域に合わない文字が出ることがあります（neonSign の文字がランダム）。地域ごとに文字の候補を分けると良くなります。
- **到着時のトースト**: マップ移動・タクシー・レベルアップ・SNS 投稿が重なると中央上にトーストが4〜5個並びます（見た目だけ）。
- **ボスの硬さ（バランス）**: 未調整（v1 から継続）。
- **デバッグパネル**: 右側のクエストトラッカーに重なります（デバッグ用なので許容）。
