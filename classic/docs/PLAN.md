# PLAN — 作る順番

> 目次に戻る: [DESIGN.md](DESIGN.md)
> 新作は `classic/` の下に独立して置く。今の NEON VICE STORY（`src/`・`docs/`・`tests/`）は**変えない**。流用する時はファイルを `classic/src/` へ**写して**から直す（元のファイルは触らない）。

## 1. 技術の方針

- ブラウザ（HTML5 Canvas 2D）・ビルド無し・ES Modules。今の作品と同じ。`classic/index.html` から `classic/src/main.js` を読む。
- 内部解像度 800×600 の Canvas に描き、整数倍で拡大（`imageSmoothingEnabled = false`）。
- データ（マップ・敵・装備・クエスト・スキル）は `classic/src/data/*.js`。**設計書の元データ（`classic/tools/data/*.mjs`）から作る**（`classic/tools/export_data.mjs` を M1 で作り、設計書とゲームの数値が 1 か所から出るようにする）。
- 計算式は `classic/tools/lib/combat.mjs`・`curves.mjs` を `classic/src/systems/` へ写して使う（式を二重に書かない）。
- セーブは localStorage（6 枠・倉庫は共有）。
- テストは node のユニット（式・データの検査）と Playwright のスモーク（ゲームを開いて操作して画面写真）。

## 2. マイルストーン

各マイルストーンの「完成の条件」がすべて満たせたら次へ。各マイルストーンの終わりに、デバッグ担当の通し検証と `classic/tests/smoke.mjs` 全件。

### M0 準備（設計書のまとめ）— このコミット
- 設計書 9 つと計算の道具（`classic/tools/`）。
- 完成の条件: `node classic/tools/gen_docs.mjs --check` が問題なし。ユーザーが DESIGN.md 7 章の「決めてほしい点」に答える。

### M1 エンジン
- 800×600 の Canvas・整数倍の拡大・カメラ（プレイヤーを追い、マップの端で止まる。上下は少し遅れて追う）。
- 物理: 歩く・ジャンプ・浮いた足場（↓＋ジャンプで降りる）・坂・縄・はしご・伏せ・ポータル（↑）・落下の速さの上限。
- 当たり判定: プレイヤーと敵（触れるとダメージ・無敵時間 1.5 秒・押される）、攻撃の範囲と敵。
- 16 px のタイルのマップ形式と、テスト用のマップ 3 つ（平ら・縄とはしご・段差）。
- 入力（UI.md 3 章）、セーブ（6 枠）、ドット絵の字（12 / 16 px）。
- `export_data.mjs`（設計書の元データ → `classic/src/data/`）、`pixel_fix.mjs`・`check_pixel.mjs`（絵の後処理と検査）。
- 仮の絵（四角と線）で動けばよい。
- 完成の条件: テストのマップで、縄・はしご・浮いた足場・ポータルが全部使える。1 分間動かして引っかかり・すり抜けが無い。60 fps（普通のノートパソコン）。ユニットテスト（物理・式）とスモーク（3 マップを歩く）が通る。

| 段 | いつ | 中身 | 数（目安） |

- 装備の部品は全部の Lv 帯を別の絵にしない。**形は 4 帯ごとに 1 つ**（例: 戦士の兜は Lv10〜25 / 30〜50 / 60〜90 / 100〜 の 4 形）で、**色をパレットで変えて**シリーズを作る（装備 671 の絵を、形 約 120 ＋ 色違いで済ませる）。
- アイコンは装備の部品の絵から自動で作る（立ちの 1 コマを 32×32 に収める）。足りない物だけ手で描く。

## 4. 作業の分け方（担当）

| 担当 | 主な仕事 |
|---|---|
| メイン | 全体の統合、`classic/src/main.js`、小さな修正 |
| システム | `classic/src/systems/`・`data/`（式・スキル・装備・クエストの動作）、`export_data.mjs` |
| ワールド | マップ（タイル・足場・縄・ポータル）、敵の動きと湧き |
| UI | ウィンドウ・会話・店・HUD・キー設定 |
| アート | ドット絵（AI の下絵 → `pixel_fix.mjs` → 手直し）、絵の検査 |
| サウンド | BGM・効果音 |
| デバッグ | `classic/tests/`（ユニット・スモーク・狩りの速さの自動検証） |
| リサーチ（設計） | 設計書（`classic/docs/`）と `classic/tools/` の数値の見直し |

## 5. 設計書の数値を直す時

1. `classic/tools/data/*.mjs`（名前・Lv・つながり等）か `classic/tools/lib/*.mjs`（式・カーブ）を直す。
2. `node classic/tools/gen_docs.mjs` で表を作り直す（つじつまの検査も走る）。
3. 狩りの速さ: `node classic/tools/hunt_speed.mjs`、職ごとの釣り合い: `node classic/tools/balance_check.mjs`。
4. 手書きの文（あらすじ・説明）は各 .md を直接直す。
